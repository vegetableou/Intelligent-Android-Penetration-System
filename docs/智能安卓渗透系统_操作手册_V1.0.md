## 第一章　引言

### 1.1　编写目的

本手册依据《智能安卓渗透系统》（以下简称"本系统"或"系统"）V1.0 版本的功能设计与实际运行情况编写而成，旨在为系统的部署人员、运营管理人员及最终使用人员提供完整、准确、可操作的使用指引。通过阅读本手册，读者可全面了解系统的整体架构、各功能模块的操作流程及注意事项，从而正确、高效地使用本系统完成安全检测与评估任务。

本手册所描述的系统功能均以 V1.0 版本为基准。如后续版本发生功能变更，请参阅对应版本的更新说明。本手册不涉及底层算法原理的详细推导，如需深入了解算法实现，请参阅同期发布的《软件设计说明书》。

### 1.2　适用范围

本手册适用于以下场景：

（1）在满足运行环境要求的服务器或工作站上完成系统部署与初始化配置；

（2）通过 Web 浏览器界面访问系统，执行目标侦察、漏洞检测、载荷投递、会话管理等安全评估操作；

（3）对系统运行过程中产生的告警、日志及攻击结果进行查阅与管理；

（4）对系统核心配置参数（包括 Ngrok 隧道令牌、GoPhish API 密钥、Metasploit 监听端口等）进行维护更新。

本手册适用的软件版本为 V1.0，操作系统平台为 Kali Linux（推荐）或其他基于 Debian 的 Linux 发行版。

### 1.3　读者对象

本手册面向以下读者群体：

**系统管理员**：负责系统的安装、部署、配置及日常维护，需具备 Linux 基础操作能力和网络基础知识。

**安全测试工程师**：使用系统执行授权渗透测试任务，需具备网络安全基础知识，熟悉 Metasploit、Nmap 等常见安全工具的基本概念。

## 第二章　软件概述

### 2.1　软件简介

智能安卓渗透系统是一套面向授权安全评估场景的自动化渗透测试平台，以 Python/Flask 为核心构建 Web 服务，整合了目标侦察、漏洞利用、载荷投递、会话管理和攻击结果分析等完整渗透测试链条。系统通过浏览器界面向用户提供图形化操作入口，无需逐条输入命令行指令，大幅降低安全测试的操作门槛，同时通过标准化流程保证测试结果的可重复性与可追溯性。

【图1：系统主控制面板首页截图】

### 2.2　主要功能模块

本系统共包含九个核心功能模块，各模块之间既可独立运行，也可按攻击链路协同调用：

（1）**目标扫描模块**：集成 Nmap 端口扫描、FFuf 目录爆破和 Nuclei 漏洞模板扫描，输出综合侦察报告。

（2）**钓鱼攻击模块**：通过 GoPhish 平台创建并投递网络钓鱼活动，支持自定义邮件模板与仿冒落地页，结合 Ngrok 实现公网可访问的钓鱼页面。

（3）**文件上传攻击模块**：自动探测目标 Web 应用的文件上传端点，尝试多种绕过技术将恶意 APK 上传至目标服务器。

（4）**SQL 注入检测模块**：调用 SQLMap 对指定目标 URL 进行 SQL 注入扫描，支持数据库枚举与数据提取。

（5）**会话管理模块**：展示并管理已建立的 Meterpreter 会话，支持远程命令执行与后渗透模块调用。

（6）**攻击结果模块**：汇总展示各模块的测试结果，支持按时间、类型过滤查看。

（7）**MSF RPC 帮助模块**：提供 Metasploit MSFRPC 服务的配置说明与快捷操作指引。

（8）**系统配置信息模块**：集中展示当前生效的所有配置参数，包括各服务密钥、端口用途说明等，方便运维人员快速核查。

（9）**控制面板**：展示系统整体运行状态，包括各集成服务的连接情况和 LHOST 配置。

### 2.3　系统整体架构

本系统采用经典的 B/S（浏览器/服务器）架构。后端由 Flask 2.3.3 提供 Web 服务，通过 PyYAML 读取配置文件，调用各核心功能模块；前端使用 Bootstrap 5 + Font Awesome 6 构建响应式界面，通过 Fetch API 与后端 RESTful 接口通信，实现无刷新的异步操作体验。

## 第四章　软件安装与配置

### 4.1　获取软件

从授权渠道获取系统安装包（ZIP 格式），将其解压至目标服务器的工作目录，例如 `/home/kali/android-pentest-framework-file/`。目录结构如下：

```
android-pentest-framework-file/
├── run.py                  # 系统启动入口
├── requirements.txt        # Python 依赖清单
├── docker-compose.yml      # Docker 编排配置
├── Dockerfile              # Docker 镜像构建文件
├── config/
│   └── config.yaml         # 系统核心配置文件
├── core/                   # 核心功能模块
├── web/
│   ├── app.py              # Flask Web 应用
│   ├── templates/          # Jinja2 HTML 模板
│   └── static/             # CSS / JS 静态资源
├── payloads/               # 生成的 APK 载荷存放目录
└── logs/                   # 运行日志目录
```

### 4.2　依赖安装（非 Docker 方式）

打开终端，进入系统根目录，执行以下命令安装 Python 依赖：

```bash
cd /home/kali/android-pentest-framework-file
pip install -r requirements.txt
```

依赖安装完成后，确认 Metasploit、Nmap、SQLMap、APKTool、GoPhish、Ngrok 已正确安装并可在系统 PATH 中访问。可通过以下命令逐一验证：

```bash
msfconsole --version
nmap --version
sqlmap --version
apktool --version
gophish --version
ngrok version
```

若上述命令均返回版本信息，则说明依赖环境满足要求。

### 4.4　核心配置文件说明

系统的所有可配置参数集中存储于 `config/config.yaml`，该文件是唯一的配置源，核心模块在运行时均从此文件读取参数，严禁在代码文件中硬编码敏感信息。配置文件各节说明如下：

**（1）应用基础配置（app 节）**

```yaml
app:
  name: "Android自动化渗透测试框架"
  version: "1.0"
  debug: true
```

`debug` 设置为 `true` 时，Flask 将在代码变更后自动重载，并在出错时显示详细堆栈；生产环境建议改为 `false`。

**（2）Ngrok 配置（ngrok 节）**

```yaml
ngrok:
  auth_token: "YOUR_NGROK_AUTH_TOKEN"
  enabled: true
  default_port: 8080
```

`auth_token` 为 Ngrok 平台账号的身份验证令牌，需登录 ngrok.com 获取并填入。`default_port` 为 Ngrok 隧道转发的本机端口，默认 `8080`。

**（3）GoPhish 配置（gophish 节）**

```yaml
gophish:
  enabled: true
  api_key: "YOUR_GOPHISH_API_KEY"
  base_url: "https://localhost:3333"
  admin_url: "https://localhost:3333"
```

`api_key` 为 GoPhish 后台生成的 API 密钥，首次启动 GoPhish 服务后在其 Web 界面的"Account Settings"页面中生成。`base_url` 为 GoPhish API 的访问地址。

**（4）Metasploit 配置（metasploit 节）**

```yaml
metasploit:
  default_payload: "android/meterpreter/reverse_tcp"
  default_lhost: "0.0.0.0"
  default_lport: 4444
  msfrpc_password: "YOUR_MSFRPC_PASSWORD"
  msfrpc_port: 55553
  msfrpc_auto_start: false
```

`default_lhost` 为系统默认监听地址，`default_lport` 为监听端口，`msfrpc_password` 为 MSFRPC 服务的访问密码，应与启动 `msfrpcd` 时设置的密码一致。`msfrpc_auto_start` 设为 `true` 时，系统会在启动时尝试自动启动 MSFRPC 服务。

**（5）隐身配置（stealth 节）**

```yaml
stealth:
  default_level: "medium"
  available_encoders:
    - "x86/shikata_ga_nai"
    - "x86/jmp_call_additive"
  max_iterations: 10
```

`default_level` 控制 Payload 混淆编码的强度，`low` 表示无编码，`medium` 表示单次编码，`high` 表示多次迭代编码。`max_iterations` 为最大编码迭代次数。

**（6）Web 服务配置（web 节）**

```yaml
web:
  host: "0.0.0.0"
  port: 5000
  debug: true
```

`host` 设为 `0.0.0.0` 表示监听所有网络接口，`port` 为 Web 管理界面的访问端口。

## 第五章　软件操作说明

### 5.1　系统初始化

**用户目标**：在正式开展测试任务前，完成系统控制器的初始化，绑定本机监听地址。

**操作步骤**：

（1）打开浏览器，访问系统首页 `http://<服务器IP>:5000`，系统将自动跳转至控制面板页面。

（2）若控制器尚未初始化，页面顶部将显示初始化提示区域，用户在"LHOST"输入框中填写本机的实际 IP 地址（即目标主机将反向连接的监听地址）。

（3）点击"初始化系统"按钮，系统后台将调用 `/api/init` 接口，完成控制器实例的创建，并将 LHOST 值存入 Session。

（4）初始化成功后，页面顶部导航栏的"LHOST"标签将实时更新显示已绑定的 IP 地址，状态指示点变为绿色常亮。

**预期结果**：LHOST 标签显示正确的本机 IP，控制面板各模块状态指示灯变为"已就绪"状态，系统可正常接受后续操作指令。

### 5.3　目标扫描模块

**用户目标**：对指定 IP 或域名执行多维度侦察扫描，获取目标服务列表与潜在漏洞信息，为后续攻击决策提供依据。

**操作步骤**：

（1）在右侧悬浮导航面板中点击"目标扫描"，进入扫描操作界面。

（2）在"目标地址"输入框中填写待扫描的 IP 地址、CIDR 网段或域名，例如 `192.168.1.1` 或 `192.168.1.0/24`。

（3）选择扫描类型：

- **端口扫描**：调用 Nmap 对目标执行 `-sV -sS --script vuln` 综合扫描，探测开放端口、服务版本及常见漏洞；
- **目录爆破**：调用 FFuf 对目标 Web 服务执行路径枚举，发现隐藏目录与敏感文件；
- **漏洞模板扫描**：调用 Nuclei 基于预定义漏洞模板对目标进行批量检测；
- **综合扫描**：依次执行上述三种扫描并汇总结果，由决策引擎推荐最优攻击路径。

（4）设置扫描超时时间（默认 300 秒），点击"开始扫描"按钮。

（5）扫描执行期间，页面将以实时日志形式滚动显示扫描进度，不可中途关闭浏览器标签页，否则将中断当前任务。

（6）扫描完成后，结果将自动展示于下方"扫描结果"区域，并可跳转至"攻击结果"页面查看完整报告。

**预期结果**：扫描完成后展示目标开放的端口与服务列表、目录枚举结果及已识别的漏洞 CVE 列表；综合扫描模式下，决策引擎将给出推荐的攻击向量及优先级排序。

### 5.4　钓鱼攻击模块

### 5.6　文件上传攻击模块

**用户目标**：对存在文件上传功能的目标 Web 应用执行渗透测试，通过多种绕过技术将恶意 APK 上传至服务器并尝试触发执行。

**操作步骤**：

（1）在右侧悬浮面板中点击"文件上传攻击"，进入攻击配置界面。

（2）在"目标 URL"输入框中填写目标 Web 应用的根地址，例如 `http://192.168.1.100`。

（3）**自动探测模式**：勾选"自动探测上传端点"，系统将在目标 URL 基础上自动尝试以下常见上传路径：`/upload`、`/admin/upload`、`/api/upload`、`/file/upload`、`/upload.php` 等。最多尝试 `config.yaml` 中 `file_upload.max_endpoints_to_try`（默认 5）个端点。

（4）**手动指定端点**：若已知上传接口地址，可取消勾选自动探测，直接在"上传端点"输入框中填写完整接口路径。

（5）选择绕过技术（Bypass Technique）：

- **double_extension**：使用双后缀，如 `test.apk.jpg`，绕过基于扩展名的白名单；
- **null_byte**：使用空字节截断，如 `test.apk%00.jpg`；
- **case_insensitive**：大小写混合扩展名，如 `test.ApK`；
- **trailing_dots**：末尾追加点号，如 `test.apk.`；
- **trailing_spaces**：末尾追加空格，如 `test.apk `；
- **none**：不使用绕过技术，直接以原始扩展名上传。

（6）选择 Payload 架构和隐身等级（与钓鱼攻击模块配置相同）。

（7）点击"执行上传攻击"按钮，系统将自动生成 APK、探测端点、选择绕过技术并依次尝试上传。

（8）上传结果将以列表形式展示，包含每个端点的响应状态码、响应体摘要及上传置信度评分。置信度超过 `config.yaml` 中 `file_upload.confidence_threshold`（默认 30%）的结果将被标记为"可能成功"。

**预期结果**：至少一个上传端点返回成功响应，置信度评分超过阈值，APK 文件已存储于目标服务器；若目标应用支持文件执行，Meterpreter 会话将随之建立。

## 第六章　异常处理与常见问题

### 6.1　系统启动异常

**问题 1：执行 `python run.py` 后提示 `ModuleNotFoundError`**

**原因**：Python 依赖包未正确安装，或当前 Python 环境不是安装依赖时使用的虚拟环境。

**解决方法**：
（1）确认在系统根目录中执行了 `pip install -r requirements.txt`；
（2）若使用虚拟环境，确保已激活对应的虚拟环境后再执行启动命令；
（3）若仍报错，尝试指定 Python 版本：`python3 run.py`。

**问题 2：启动后浏览器访问 `http://127.0.0.1:5000` 无响应**

**原因**：5000 端口被其他进程占用，或防火墙规则阻止了该端口的访问。

**解决方法**：
（1）执行 `netstat -tlnp | grep 5000` 查看端口占用情况；
（2）若被占用，在 `config.yaml` 的 `web.port` 字段修改为其他可用端口后重启服务；
（3）检查本机防火墙规则，确认允许访问该端口：`ufw allow 5000/tcp`。

### 6.2　GoPhish 相关异常

**问题 3：控制面板显示 GoPhish 状态为"离线"**

**原因**：GoPhish 服务未启动，或 `config.yaml` 中配置的 API 密钥/地址有误。

**解决方法**：
（1）确认 GoPhish 进程正在运行：`ps aux | grep gophish`；
（2）手动启动 GoPhish：进入 GoPhish 安装目录，执行 `./gophish`；
（3）访问 GoPhish 管理界面 `https://localhost:3333`，在账户设置页面生成新的 API Key；
（4）将新生成的 API Key 更新至 `config.yaml` 中的 `gophish.api_key` 字段；
（5）重启本系统后重新检查状态。

**问题 4：发送钓鱼邮件失败，提示 SMTP 连接错误**

**原因**：GoPhish SMTP 发件配置有误，或发件服务器连接超时。

**解决方法**：
（1）进入 GoPhish 管理界面的"Sending Profiles"页面，检查 SMTP 服务器地址、端口、用户名和密码；
（2）点击"Send Test Email"按钮测试 SMTP 连通性；
（3）若使用公共邮件服务（如 Gmail），需开启"低安全性应用访问"或使用应用专用密码。

### 6.3　Metasploit / MSFRPC 相关异常

**问题 5：会话管理页面提示"MSFRPC 连接失败"**

**原因**：Metasploit MSFRPC 服务未启动，或连接密码配置不一致。

**解决方法**：
（1）手动启动 MSFRPC 服务，在终端执行：
```bash
msfrpcd -P <YOUR_PASSWORD> -p 55553 -a 127.0.0.1 -S
```
其中 `<YOUR_PASSWORD>` 需与 `config.yaml` 中 `metasploit.msfrpc_password` 的值完全一致；
（2）确认端口监听已建立：`netstat -tlnp | grep 55553`；
（3）重新进入控制面板点击"检查服务状态"按钮刷新连接状态。

**问题 6：生成 APK Payload 失败，提示 msfvenom 命令不存在**

**原因**：Metasploit Framework 未正确安装，或 `msfvenom` 未加入系统 PATH。

**解决方法**：
（1）执行 `which msfvenom` 确认命令路径；
（2）若未找到，重新安装 Metasploit：`sudo apt install metasploit-framework`；
（3）安装完成后重启终端并再次尝试生成操作。

### 6.4　Ngrok 相关异常

**问题 7：Ngrok 隧道建立失败，提示 Auth Token 无效**

**原因**：`config.yaml` 中的 Ngrok Auth Token 填写有误或已过期。

**解决方法**：
（1）登录 ngrok.com，在"Your Authtoken"页面复制最新的令牌；
（2）将新令牌更新至 `config.yaml` 中的 `ngrok.auth_token` 字段；
（3）重启系统服务后重试。

**问题 8：Ngrok 隧道正常，但目标无法访问 APK 下载链接**

**原因**：Ngrok 免费账户有并发连接数限制，或文件分发服务（8080 端口）未启动。

**解决方法**：
（1）检查 8080 端口的 HTTP 服务是否正在运行；
（2）尝试在浏览器中手动访问 Ngrok 提供的公网 URL，确认内容可正常加载；
（3）若 Ngrok 频繁断线，考虑升级至付费账户以获得稳定的隧道服务。

### 6.5　配置文件相关异常

**问题 9：系统启动后配置信息页面显示字段均为空或默认值**

**原因**：`config/config.yaml` 文件不存在，或 YAML 格式有语法错误。

**解决方法**：
（1）确认文件路径 `config/config.yaml` 存在（以系统根目录为基准）；
（2）使用在线 YAML 校验工具（如 yamllint.com）检查配置文件语法；
（3）常见语法错误包括：冒号后缺少空格、缩进使用了 Tab 而非空格、字符串未加引号等。

### 附录 C　日志文件说明

系统运行日志默认写入 `logs/app.log`，日志格式如下：

```
2024-01-15 10:23:45,123 - INFO - core.scanner - Nmap 扫描启动，目标: 192.168.1.100
2024-01-15 10:24:02,456 - INFO - core.scanner - Nmap 扫描完成，发现开放端口: [22, 80, 443]
2024-01-15 10:24:05,789 - WARNING - core.gophish_client - GoPhish 服务连接超时，将在需要时重试
```

日志级别在 `config.yaml` 的 `logging.level` 字段设置，可选值为 `DEBUG`、`INFO`、`WARNING`、`ERROR`。生产环境建议设置为 `INFO` 或 `WARNING`，以避免 `DEBUG` 级别日志中可能出现的敏感信息记录。
